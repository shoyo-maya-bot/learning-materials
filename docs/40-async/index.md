# 40 非同期処理

この章群では、処理を「その場で待たずに後で行う」ための考え方と仕組みを学びます。
対象は Java のスレッド、Spring の `@Async`、AWS の SQS（メッセージキュー）です。
目安の期間は **3 日** です。

!!! abstract "この章群の到達目標"
    - 同期処理と非同期処理の違いと、どちらを選ぶかの判断基準を説明できる
    - 外部呼び出しにタイムアウトを設定する理由を説明できる
    - SQS の「少なくとも 1 回の配信」を前提に、冪等な受信処理を書ける
    - 再試行・デッドレターキュー・可視性タイムアウトの関係を説明できる

## 前提

- [20 基礎](../20-basics/index.md) を終えていること（特にトランザクションと例外処理）
- [30 実ソース読解](../30-reading/index.md) で注文ファイル取込バッチ（JOB0001）を読んでいること

!!! note "サンプルアプリと非同期処理"
    sample-app には、`@Async` や SQS を使うコードはありません。
    API もバッチも、1 つのスレッドで上から順に処理する同期処理です。
    この章群では「例:」のコードで説明し、近い実物として次を参照します。

    - クラウド構成の SQS（`dev-environment` の `cloud/modules/sqs-queue`）
    - ジョブフローの再試行（`cloud/modules/batch-workflow` の `Retry`）
    - 再実行しても重複しない登録（`sample-app/src/main/resources/mapper/OrderMapper.xml` の `insertIfAbsent`）

# 70 クラウドとアーキテクチャ

この章群では、要件定義などの上流工程と、クラウド（AWS・Azure）でのアーキテクチャ設計を学びます。
「コードを書く」から一歩進んで、「要件から構成を選び、その理由を説明できる」ことを目指します。
資格（AWS Certified Solutions Architect – Associate と Azure の各試験）の範囲も、あわせて押さえます。
目安の期間は **4〜5 か月**（1 日 1〜2 時間）です。

!!! abstract "この章群の到達目標"
    - 非機能要件（可用性・性能・運用・移行・セキュリティ・環境）を数字で書ける
    - 単一障害点・ステートレス・疎結合の観点で、構成図の弱いところを指摘できる
    - AWS の主要サービスを「何をするか・いつ選ぶか・似たものとの違い」で説明できる
    - 要件（RTO / RPO・コスト）から、構成と DR の戦略を選べる
    - AWS で設計した構成を、Azure のサービスに置き換えて説明できる

## 前提

- [10 環境構築](../10-setup/index.md) で、sample-app を自分の PC で動かしていること
- [30 実ソース読解](../30-reading/index.md) の [30-12 ファイルの取得（S3）](../30-reading/30-12-file-fetcher-s3.md) を読んでいること
- [40-02 キュー・再試行・冪等性](../40-async/40-02-queue-retry-idempotency.md) と [60-01 設計書の書き方](../60-quality/60-01-design-doc.md) を読んでいると、理解が早くなります

この章群の「サンプルアプリでは」は、dev-environment の `cloud/`（Terraform）を読みます。
sample-app を AWS 上で動かすための構成です。

## 学習の進め方

設計の考え方（70-01・70-02）を先に学び、次に AWS で具体化（70-03〜70-05）します。
Azure（70-06）は、AWS との対応で覚えると早く進みます。

| 時期 | 章 | ゴール |
| --- | --- | --- |
| 1〜2 週目 | 70-01・70-02 | 非機能要件を数字で書ける。RTO / RPO を説明できる |
| 3〜6 週目 | 70-03・70-04 と手を動かす練習 | VPC・コンテナ（または EC2）・DB・S3 の構成を自分で作れる |
| 7〜10 週目 | 70-05 と各章の理解度チェック | 「要件 → 構成」を自分で選べる |
| 11〜12 週目 | 70-07 | AWS Certified Solutions Architect – Associate に合格する |
| 13 週目〜 | 70-06 | Azure の基礎試験から始め、担当に応じて上位の試験へ |

!!! warning "クラウドで手を動かす前に"
    AWS・Azure の個人アカウントで練習するときは、最初に **予算のアラート** を設定してください。
    NAT ゲートウェイや DB は、起動しているだけで費用がかかります。
    練習で作ったものは、その日のうちに削除します（Terraform なら `terraform destroy`）。
    会社のアカウントで試すときは、必ず管理者の許可を得てください。

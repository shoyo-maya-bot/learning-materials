# 70-07 資格試験対策（AWS・Azure）

!!! abstract "到達目標"
    - AWS Certified Solutions Architect – Associate と Azure の各試験の範囲と順番を説明できる
    - 問題文のキーワード（運用の手間・費用・可用性など）から、答えの方向を判断できる
    - 誤りの選択肢が「なぜ違うのか」を説明できる
    - 試験の知識を、実際の構成のレビューに使える

## 何か

この章群で学んだ内容は、次の資格の範囲と重なっています。
情報は 2026 年 10 月時点のものです。
試験の内容は改訂されるので、受ける前に必ず公式の試験ガイドを確認してください。

| 試験 | 位置づけ | 形式 | 範囲と配点 |
| --- | --- | --- | --- |
| [AWS Certified Solutions Architect – Associate（SAA-C03）](https://aws.amazon.com/certification/certified-solutions-architect-associate/) | AWS の設計の中級。**最初の目標** | 130 分・65 問・150 USD・日本語あり・3 年有効 | セキュアな設計 30% / 回復力のある設計 26% / 高性能な設計 24% / コストを最適化した設計 20% |
| AWS Certified Cloud Practitioner | AWS の入門 | — | IT の実務経験があれば、飛ばして SAA から始めてよい |
| AZ-900（Azure Fundamentals） | Azure の入門 | — | クラウドの概念、Azure の主なサービス、管理とガバナンス |

AWS の試験は、1 つ合格すると次の試験を 50% 引きで受けられます。

## なぜ必要か

資格は、知識を体系的に学ぶための **道しるべ** として使います。
上流工程やアーキテクチャの知識は範囲が広く、何から学べばよいか迷いがちです。
試験の範囲に沿って学ぶと、抜けが少なくなります。

とくに SAA は、サービス名の暗記ではなく「要件からどの構成を選ぶか」を問います。
この章群の目標（要件から構成を選び、理由を説明できる）と、ほぼ同じです。

また、お客さんや他のチームに対して、知識の水準を短く示す手段にもなります。
ただし、資格を持っていることと、実際の構成を設計できることは別です。
必ず、手を動かす練習と組み合わせてください。

## どうやるか

### SAA の勉強の順番（6〜8 週）

1. **初日に模擬試験を 1 回解く**（解けなくてよい）。苦手な分野を知る
2. 70-03〜70-05 と、公式の試験ガイドで全体をつかむ
3. 手を動かす: VPC → コンテナか EC2 ＋ ALB → DB のマルチ AZ → S3 ＋ CloudFront → Lambda ＋ API Gateway
4. 問題を繰り返し解く: AWS Skill Builder の公式の練習問題、市販の問題集、模擬試験
5. 試験の 1 週間前は、正答率の低い分野に集中する（多くの人は IAM とネットワーク）

!!! failure "悪い例"
    正解の選択肢と解説の最初の 1 行だけを読み、次の問題へ進む。
    同じ形の問題で、違う条件を出されると解けません。

!!! success "良い例"
    **誤りの選択肢それぞれについて、なぜ違うのか** を自分の言葉で書く。
    「A は可用性は上がるが費用が最小ではない」「C は要件の RPO を満たさない」のように。
    条件が変わったときに、どの選択肢が正解になるかまで考えられるようになります。

### 問題文のキーワードと、答えの方向

| 問題文のキーワード | 選ぶ答えの方向 |
| --- | --- |
| 運用の手間を最小に | マネージド・サーバーレス（Lambda、Fargate、Aurora Serverless、DynamoDB） |
| 最も費用対効果が高い | 要件をちょうど満たす、最も安い構成 |
| 高可用性、AZ の障害に耐える | マルチ AZ（ALB ＋ 自動の増減、DB のマルチ AZ） |
| 疎結合、急な処理の増加を吸収 | SQS をはさむ |
| 複数の宛先に同時に通知 | SNS（＋ SQS でファンアウト） |
| 読み取りの負荷が高い | リードレプリカ、ElastiCache、CloudFront |
| インターネットを通らずに S3 へ | VPC エンドポイント（ゲートウェイ型） |
| 認証情報をコードに書かない | IAM ロール、Secrets Manager |
| 誰が API を操作したか | CloudTrail |
| 世界中の利用者に低遅延で配信 | CloudFront（HTTP）、Global Accelerator（TCP / UDP） |
| 中断してもよいバッチ | スポットインスタンス |
| 共有のファイルシステム | EFS（Windows なら FSx for Windows File Server） |

### Azure の試験の勉強

- **Microsoft Learn**（無料）の学習パスが、最も大切な教材です
- 各試験のページに、無料の「練習評価」があります。安定して合格点（1000 点中 700 点）を超えるまで繰り返します
- AZ-104 は「どう設定するか」、AZ-305 は「どれを選ぶか」を問います
- AZ-305 の問題の作りは SAA に近いので、SAA の後なら取り組みやすくなります
- 無料のアカウントで、Entra ID のユーザー作成、RBAC の割り当て、VNet と NSG、ストレージの冗長性を一通り触ります

## サンプルアプリでは

dev-environment の `cloud/` の構成を、SAA の問題の形で読みます。
実際の構成を題材にすると、試験の知識が実務の判断につながります。

**問題 A**: sample-app の prod 環境の API は、ECS Fargate で 2 台が常に動いています。
朝の 9 時台だけアクセスが 3 倍になり、応答が遅くなります。
運用の手間を増やさず、費用も抑えたいとき、どうしますか。

<!-- src: cloud/environments/prod/main.tf#L8-L8 @main -->
```hcl title="cloud/environments/prod/main.tf（8 行目）"
  api_desired_count      = 2
```

- A. `api_desired_count` を 6 に増やす
- B. ECS サービスの自動の増減（ターゲット追跡。CPU 使用率など）を設定し、最小 2 台・最大 6 台にする
- C. タスクの CPU とメモリを最大にする
- D. EC2 に移して、リザーブドインスタンスを買う

??? note "答え"
    **B** です。負荷に合わせて台数が自動で増減し、9 時台以外は 2 台に戻るので費用も抑えられます。
    A は一日中 6 台分の費用がかかります。C はスケールアップで、上限があるうえ常に費用が高くなります。
    D は運用の手間（サーバーの管理）が増えます。

**問題 B**: dev1 環境は NAT ゲートウェイを作りません。
private サブネットのバッチが、S3 から入力ファイルを読めるようにするには、どうしますか。

- A. バッチを public サブネットに移し、公開の IP を付ける
- B. NAT ゲートウェイを作る
- C. S3 のゲートウェイ型 VPC エンドポイントを作り、private のルートテーブルに関連付ける
- D. S3 バケットを公開にする

??? note "答え"
    **C** です。追加の費用なしに、インターネットを通らず S3 に届きます。
    A と D はセキュリティを下げます。B は動きますが、費用を抑えるという dev1 の方針に反します。
    なお、コンテナイメージの取得には、ECR 用のインターフェイス型エンドポイントも必要です。

## もし資格の範囲を道しるべにしなかったら？

クラウドの勉強を、目の前の案件で使うサービスだけで進めたとします。
ECS と S3 には詳しくなりますが、DR の戦略や、ネットワーク ACL、リードレプリカのことは知らないままです。
設計レビューで「リージョンの障害のときは」と聞かれても、選択肢そのものを思い付けません。

試験の範囲に沿って学ぶと、今は使わない選択肢も「知っている」状態になります。
設計は、選択肢を並べて比べる仕事です。
知らない選択肢は、比べることもできません。

## 理解度チェック

1. EC サイトの Web サーバー（EC2 1 台）が、セールのときにアクセスの集中で落ちます。運用の手間を増やさずに、可用性と拡張性を上げるにはどうしますか。

    ??? note "答え"
        ALB と、複数の AZ にまたがる Auto Scaling グループにします。
        セッションは ElastiCache などに移し、サーバーをステートレスにします。
        インスタンスを大きくするだけ（スケールアップ）では、1 台のままで単一障害点が残ります。

2. 注文の受付の後に重い集計があり、ピーク時に注文画面がタイムアウトします。注文を取りこぼしてはいけません。どうしますか。

    ??? note "答え"
        受付で SQS にメッセージを入れ、処理役が非同期で集計します。
        メッセージはキューに残るので、取りこぼしません。受信処理は冪等にします。

3. private サブネットの EC2 から、S3 の大量のログを読み書きしています。NAT ゲートウェイのデータ処理の料金が高いです。どうしますか。

    ??? note "答え"
        S3 のゲートウェイ型 VPC エンドポイントを作ります。
        ゲートウェイ型は追加の料金がかからず、S3 への通信が NAT ゲートウェイを通らなくなります。

4. EC2 のアプリが、S3 を使うためのアクセスキーを設定ファイルに書いています。セキュリティの改善は何ですか。

    ??? note "答え"
        必要最小限の権限を持つ IAM ロールを EC2 に付け、アクセスキーを削除（無効化）します。
        キーを暗号化したり、定期的に入れ替えたりするより、キーを持たないほうが安全です。

5. 要件が「RTO 4 時間、RPO 1 時間、費用は最小」で、東京リージョン全体の障害に備えます。どの DR 戦略を選びますか。

    ??? note "答え"
        大阪リージョンへの「バックアップと復元」です（1 時間ごとにスナップショットを複製し、IaC で作り直す）。
        東京の中のマルチ AZ だけでは、リージョン全体の障害に耐えられません。
        マルチサイトやウォームスタンバイは、要件に対して費用が過剰です。

## コードを読むときの確認観点

- [ ] 構成の判断を、試験のキーワード（運用の手間・費用・可用性・セキュリティ）で説明できるか
- [ ] 「もっと安い構成で要件を満たせないか」を確かめたか
- [ ] 誤りの選択肢に当たる構成（スケールアップだけ、公開の S3、アクセスキー）が紛れていないか
- [ ] 台数が固定のサービスに、自動の増減が必要かを検討したか
- [ ] 公式の試験ガイドとドキュメントで、サービスの最新の仕様を確かめたか

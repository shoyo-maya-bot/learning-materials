# 質問のコツ

分からないことを質問するのは、仕事の一部です。
ただし、聞き方によって、答えが返るまでの時間が大きく変わります。
このページでは、相手がすぐに答えられる質問の書き方をまとめます。

## 15 分ルール

!!! info "15 分調べて進まなければ聞く"
    1 つの問題で 15 分調べても前に進まないときは、質問してください。
    「まだ自分で頑張るべきか」と迷う時間は、たいていもったいない時間です。

    逆に、調べずにすぐ聞くのも避けます。エラーメッセージを読み、[つまずき集](troubleshooting.md) を見て、
    1 つか 2 つ試してから聞くと、質問の中身が具体的になります。

15 分の使い方の目安:

1. エラーメッセージを最初から読む（最初に出たエラーを探す）
2. [つまずき集](troubleshooting.md) と、関係する章を見る
3. [外部参照](references.md) の公式ドキュメントや、エラーメッセージで検索する
4. 仮説を立てて 1 つずつ試す。試したことと結果をメモする

## 質問に含めるもの

| 項目 | 書くこと | 例 |
|---|---|---|
| 目的 | 何をしようとしているか | sample-app の API を `bootRun` で起動したい |
| 起きていること | 実行したコマンドと、出たエラーの **全文** | `./gradlew bootRun --args='...'` で `Connection refused` |
| 期待すること | 本来どうなるはずか | `Started SampleApplication` と出る |
| 試したこと | 何を試し、結果がどうだったか | `docker compose ps` で `db` が `unhealthy` だった |
| 環境 | OS・ターミナル・ソフトの版 | Windows 11、Git Bash、Corretto 17.0.x、Rancher Desktop x.y |
| 仮説 | 自分が原因だと思っていること（無ければ「分からない」） | メモリ不足で DB が起動していないのでは |

!!! failure "悪い例"
    「sample-app が動きません。どうすればいいですか」。
    何をして、何が起きたのかが分からず、相手は質問を返すところから始めることになります。

!!! success "良い例"
    目的・コマンド・エラーの全文・試したこと・環境を書き、「次に何を確かめればよいか教えてください」と聞く。
    相手は読むだけで状況が分かり、すぐに答えられます。

### エラーは「全文」をテキストで

- スクリーンショットだけでなく、テキストで貼ります（検索やコピーができるため）
- 最後の数行だけでなく、最初のエラーを含む範囲を貼ります
- 長い場合は、コードブロック（` ``` `）で囲みます

!!! danger "貼る前に伏せる"
    パスワード・アクセスキー・トークン・`.env` の中身・顧客の個人情報は、質問に含めないでください。
    ログに含まれている場合は `****` などで伏せてから貼ります。

## 質問のテンプレート

チャットにそのまま貼って使えます。

```markdown
## やりたいこと
（例: sample-app の API をローカルで起動したい）

## 実行したコマンド
（例: ./gradlew bootRun --args='--spring.profiles.active=local'）

## 起きていること（エラー全文）
（ここに貼る）

## 期待していたこと
（例: Started SampleApplication と出て、curl で会員 1 の JSON が返る）

## 試したこと
- （例: docker compose ps → db が unhealthy）
- （例: つまずき集の「コンテナが起動しない」を確認 → メモリは 4GB に設定済み）

## 環境
- OS / ターミナル: （例: Windows 11 / Git Bash）
- java -version: （結果）
- その他: （Rancher Desktop の版など）

## 自分の仮説
（例: DB のコンテナが起動に失敗しているのでは）
```

## AI に聞くか、人に聞くか

GitHub Copilot Chat などの AI は、いつでもすぐに答えてくれる便利な相手です。
ただし、得意なことと苦手なことがあります。

| AI に向いている質問 | 人に聞くべき質問 |
|---|---|
| エラーメッセージの意味、一般的な原因の候補 | チームの決まりごと（規約・ブランチの運用・ID の体系） |
| コードの読み方、標準ライブラリの使い方 | 仕様の解釈、業務上の判断、顧客との約束 |
| 調べるためのコマンドの案 | 権限・アカウント・社内の手続き |
| テストケースの観点の洗い出し | AI の答えが正しいかどうかの最終確認 |

!!! warning "AI の答えは下書き"
    AI はもっともらしい誤りを答えます。答えは自分で確かめ、採用した理由を説明できる状態にしてください。
    AI と 15 分やり取りしても解決しない場合も、15 分ルールに従って人に聞きます。
    詳しくは [10-06 GitHub Copilot の設定と使い方](../10-setup/10-06-copilot.md) を見てください。

人に聞くときは、AI に聞いた内容と答えも「試したこと」に書くと、話が早く進みます。

## 解決したら

- 質問した相手やチャンネルに「解決しました。原因は〜で、〜で直りました」と書きます
- 同じことで困る人がいそうなら、[つまずき集](troubleshooting.md) への追加を提案します
- 自分のメモにも残しておくと、次に同じことが起きたときに 1 分で直せます

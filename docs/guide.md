# 学習の進め方

## 順番

1. **第 1 週: 10 環境構築** — sample-app を自分の PC で動かし、テストを実行できるところまで
2. **第 2〜3 週: 20 基礎** — 1 日 2 章が目安。各章の「理解度チェック」を自分の言葉で答えられたら次へ
3. **第 3〜4 週: 30 実ソース読解** — 各章の演習を **先に自分で解いてから** 解答を見る
4. **担当に応じて**: API を作る人は 50、バッチ・連携を作る人は 40、設計・レビューをする人は 60、要件定義・方式設計・クラウドを担当する人は 70
5. **案件の担当者**: 最後に 00 マネジメント

## 各章の使い方

| 節 | 読み方 |
|---|---|
| 到達目標 | 読み終えたときにできること。最後にもう一度見て、できるか確かめる |
| 何か・なぜ必要か・どうやるか | 本文。悪い例と良い例を見比べる |
| サンプルアプリでは | 実際のファイルを VS Code で開いて、一緒に読む |
| もし〇〇がなかったら？ | その仕組みの価値を考える |
| 理解度チェック | 答えを開く前に、声に出すか書いて答える |
| コードを読むときの確認観点 | レビューや実案件のコードを読むときのチェックリストとして使う |

## AI（Copilot）との付き合い方

- わからないコードは Copilot に説明させてよい。ただし **説明が正しいかはコードとテストで確かめる**
- 演習の答えを Copilot に聞くのは、自分で考えた後に。考える過程が学習です
- 社外秘の情報・顧客のデータ・パスワードを Copilot に貼らない（[10-06](10-setup/10-06-copilot.md)）

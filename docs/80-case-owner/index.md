# 80 案件担当になる

この編は、**指示どおりに作業をこなす段階** から、**1 つの案件を自分で計画して進める段階** に進むためのものです。
10〜70 の編で学んだ技術を、「なぜこう書かれているか」まで説明できる力と、
見積・計画・報告を自分で回す力に結び付けます。

## 成長の 3 つの段階

開発者の成長を、次の 3 段階で考えます。この編の目標は真ん中の **案件担当** です。

| 段階 | 仕事の範囲 | 典型的な姿 |
|---|---|---|
| 作業担当 | 指示された作業 | 指示どおりに手を動かす。標準のルールに従って動くコードを書く。与えられた期間で作業を終える |
| **案件担当** | 1 つの案件 | 設計から試験までを自分で計画して進める。設計・コード・ルールの「なぜ」を理解して守る。見積・計画・可視化・報告を自分で回す |
| 業務開発リーダー | 複数の案件 | 複数の案件をまとめて意思決定する。標準やルールを作り、他の人に使わせる。計画の型を整え、プロセスを改善する |

「コードを書けること」をゴールにすると、指示どおりに書ける人が増えるだけで、案件は進みません。
案件担当に要るのは、開発のプロセス全体を自分でコントロールする力です。

## 3 つの力

| 力 | 中身 | 作業担当との違い |
|---|---|---|
| エンジニアリング力 | 設計書やコードが「なぜこう書かれているか」まで読み解き、不備を見つけて直す | 書かれたとおりに作るだけでなく、書かれた理由と影響まで分かる |
| マネジメント力 | 見積と計画を自分で立てる。遅れや課題を自分で見える形にし、報告する | 聞かれてから答えるのではなく、自分から出す |
| 当事者意識 | 指示された仕事ではなく、自分の案件としてコントロールする | 「言われたことはやった」で止まらず、案件の結果に責任を持つ |

!!! example "実践の例: 作る前に設計書を読む期間を取る"
    ある開発者は、実装に入る前に設計書を読むだけの期間を計画に入れました。
    各 STEP の「処理内容」と「処理目的」を、自分の言葉で書き出してから実装を始めました。
    目的が書けない STEP は、その場で設計者に質問しました。
    結果として、実装の途中での手戻りが減り、設計の不備も早く見つかりました。
    この演習は [80-06 設計書を読み、改善を提案する](80-06-read-design.md) で行います。

観点ごとに、3 つの段階の目安を並べます。「学ぶ章」は、案件担当の水準に必要な章です。

DI と ORM・DB は、既存の章が案件担当の水準まで扱っています。
この編では新しい章を作らず、下の「自己診断」の問いで確かめます。

## 自己診断のやり方

1. 上の表の各行で、自分が「作業担当」「案件担当」のどちらの列に当てはまるかを付けます。
   迷ったら低い方を選びます
2. 「案件担当」に付けた行は、その列の文を **人に説明して** 確かめます。
   先輩や同僚に 3 分で説明し、質問に答えられれば合格です
3. 「作業担当」に付けた行は、学ぶ章を読み、演習を解きます
4. 1〜2 か月ごとに付け直し、変化を記録します。進んだ行と止まっている行が見えます

!!! tip "DI と ORM の自己診断の問い"
    - コンストラクタ注入を、フィールドに `@Autowired` を付ける書き方より勧める理由を 2 つ言えますか（[20-07](../20-basics/20-07-spring-di.md)）
    - `@Value("${app.batch.max-input-bytes:...}")` の `:` の後ろは何ですか。設定ファイルと環境変数のどちらが勝ちますか（[20-08](../20-basics/20-08-config-profile.md)）
    - Mapper のインタフェースのメソッドと XML の `id` が食い違うと、いつ・どんなエラーになりますか（[30-08](../30-reading/30-08-mapper-sql.md)）
    - `#{}` と `${}` の違いを、SQL インジェクションの観点で説明できますか（[30-08](../30-reading/30-08-mapper-sql.md)）
    - 1 件ずつ SELECT を繰り返す処理が遅くなる理由と、直し方を言えますか（[20-11](../20-basics/20-11-sql.md)）

## 読む順番

10〜60 の編（少なくとも 20 基礎と 30 実ソース読解）を終えてから読みます。
80-01〜80-04 はマネジメント、80-05〜80-13 は技術です。
担当している案件で今いちばん困っている観点から読んで構いません。
[00 マネジメント](../00-management/index.md) と合わせて読むと、案件の全体像がつかめます。

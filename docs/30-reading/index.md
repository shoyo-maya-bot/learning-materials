# 30 実ソース読解

この節では、`dev-environment` リポジトリの sample-app を教材にして、**実際のソースコードを読む力** を身に付けます。
「20 基礎」で学んだ Java・Spring Boot・MyBatis・テストの知識を、1 つのアプリの中でつなげて読む練習です。

## この節を終えると

- 初めてのプロジェクトで、どのファイルから読み始めればよいかを自分で決められる
- API（会員の照会・登録）の要求が、コントローラから SQL までどう流れるかを説明できる
- バッチ（注文ファイル取込 JOB0001）の起動から終了コードまでを説明できる
- 設計書と実装を突き合わせて、食い違いや確認すべき点を見つけられる
- 本体を変えたとき、どのテストが落ちるか（落ちないか）を予想できる

## 所要時間

**全体で 2 週間（10 営業日）** を目安にしています。
表の目安は、本文を読み、理解度チェックと演習を解き、解答で答え合わせをするまでの時間です。
残りの日は、つまずいた章の読み直しや、自分で sample-app を少し変えて動かす時間に使ってください。

## 各章の進め方

1. 本文を読みながら、引用されたファイルを **エディタで実際に開きます**。行番号は目安なので、ずれていたら前後を探してください
2. 「理解度チェック」に答えます。答えは折りたたみの中にあります
3. 章の最後の「演習」を解きます。ソースを検索し、必要ならテストやバッチを実際に動かして確かめます
4. 解いた後で、[解答](answers/index.md) を見て答え合わせをします
5. 「実案件での読み替え」の表を見て、配属先のプロジェクトで同じものがどこにあるかを考えます

!!! warning "演習は、解答を見る前に自分で解いてください"
    この節の目的は、答えを知ることではなく **答えの探し方** を身に付けることです。
    解答を先に読むと、わかった気になっても、初めてのコードでは同じことができません。
    15 分考えても手がかりが無いときは、解答の「根拠」の 1 行目だけを見て、続きは自分で探してください。

## 演習と解答の方針

- 演習は各章 3〜5 問です。種類は主に次の 3 つです
    - **場所を探す**: 「この動きはどのファイルの何行目か」
    - **どのテストが落ちるか**: 「本体をこう変えたら、どのテストが失敗するか（しないか）」
    - **小さな変更**: 「検証やテストを 1 つ足す」など、実際に手を動かす課題
- 解答は [解答の一覧](answers/index.md) に、章ごとに分けて置いています
- 各解答には、答え・根拠（コードの場所）・よくある誤答を書いています。誤答の理由も読むと、読み違えやすい箇所がわかります
- 「小さな変更」の課題は、解いた後に `git restore` などで元に戻してから次の章へ進んでください

## 読むのは `exercise-base` ブランチ {#exercise-base}

sample-app には、教材の演習で見つけてもらうための **弱いところ** が 8 件あります。
`main` ではこれらを直したので、教材の引用・行番号・演習は、直す前のコードを残した **`exercise-base` ブランチ** に合わせています。

```bash
cd /c/work/dev-environment
git fetch origin
git switch exercise-base        # 教材を進めるとき（演習はこちらで解く）
git switch main                 # 修正後のコードを見るとき
```

!!! warning "演習の「小さな変更」は exercise-base の上で"
    `exercise-base` に直接コミットしないでください。試すときは `git switch -c my-exercise exercise-base` で自分用のブランチを作ります。

### 解いた後に: 修正後のコードと比べる

演習を解いて解答を読んだら、`main` でどう直したかを見比べてください。
自分の直し方と違っていても、間違いとは限りません。違いの理由を考えるのが、この節のいちばんの練習です。

```bash
git diff exercise-base main -- sample-app/src/main     # 本体の変更
git diff exercise-base main -- sample-app/src/test     # 増えたテスト
```

| 弱いところ | 出てくる章 | `main` での直し方 |
|---|---|---|
| 同じメールアドレスの同時登録で 500 | 30-07、60-02 | 一意制約違反（`DuplicateKeyException`）を受け止め、409 + APPE0003 にする。事前の確認は残す（よくある重複を早く返すため） |
| 存在しない会員 ID の行 1 件で、ファイル全体が取り消される | 30-08、30-11 | 登録の前に会員の存在を確かめ、その行だけ飛ばす（終了コード 4）。同じ会員は 1 回だけ確かめる |
| 桁あふれの行 1 件で、ファイル全体が取り消される | 30-10、30-11 | `order_no`・`product_code` の 20 文字を `parse` で確かめる |
| Karate の接続先（`baseUrl`）がテストに届かない | 30-02、30-15 | `build.gradle` で `-DbaseUrl` をテストの JVM に渡す。`local` 以外で未指定なら失敗させる |
| ジョブ ID の誤り・未指定でも終了コード 0 | 30-09、30-13 | `BatchJobGuard` が、該当のジョブが無ければ終了コード 8 にする |
| 想定外のエラーが `ErrorResponse` の形で返らない | 30-04、50-03 | 型違い・JSON の誤りは 400 + APPE0001、標準の 4xx は APPE0004、DB につながらないときは 503 + APPE0008、それ以外は 500 + APPE9999（中身はログだけ） |
| 404 のメッセージで ID が「1,234」になる | 30-05 | ID を文字列にしてからメッセージに埋め込む |
| バッチの異常終了ログにメッセージ ID が無い | 30-13、20-14 | バッチ用の ID（APPE0005〜0007）を足し、ログの先頭に付ける |

!!! tip "行番号がずれていたら"
    `exercise-base` は教材に合わせて固定しているので、通常はずれません。
    ずれていたら、`exercise-base` に切り替えているか確かめてください。それでもずれていたら、教材の修正を提案してもらえると助かります。

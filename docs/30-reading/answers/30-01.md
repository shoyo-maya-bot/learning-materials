## 演習 1

### 解答

```text
機能: 会員の登録（API0002）
入口: MemberController.java 36-40（@PostMapping、register）
      入力は RegisterRequest（28-29。name と email に入力チェックの注釈）
流れ: MemberController.register → MemberService.register(24-33)
      → MemberMapper.existsByEmail → MemberMapper.xml 9-11
      → MemberMapper.insert → MemberMapper.xml 13-15
データ: RegisterRequest(name, email) → MemberRecord（ID 書き戻し用）→ Member(id, name, email)
        テーブル member（local/db/init/01_schema.sql）
        応答は 201 Created、Location ヘッダ /api/v1/members/{id}、本文は Member
エラー: 入力チェック違反 → MethodArgumentNotValidException → ApiExceptionHandler.invalid(37-44) → 400 / APPE0001
        メール重複 → BusinessException(APPE0003) → ApiExceptionHandler.business(31-35) → 409
テスト: MemberControllerTest.registerThenGet / invalidInputReturns400
        MemberServiceTest.register_normalizesEmailAndAssignsId / register_rejectsDuplicateEmailIgnoringCase
        members.feature「登録した会員を照会できる」「同じメールアドレスは登録できない」
未検証: 同じメールアドレスで同時に登録されたときの動き
```

### 理由（コードの場所）

- 入口は `MemberController.java` 36 行目の `@PostMapping` です。
  クラスの `@RequestMapping("/api/v1/members")`（18 行目）と組み合わせて `POST /api/v1/members` になります。
- 39 行目の `ResponseEntity.created(URI.create("/api/v1/members/" + created.id()))` が、201 と Location を決めます。
- 重複チェックは `MemberService.java` 27〜29 行目、登録は 30〜32 行目です。
- 400 は `@Valid`（37 行目）が付いているため、入力チェック違反で例外になることから来ます。

### よくある誤答

- 「重複は DB の一意制約で 409 になる」: 409 は `existsByEmail` の事前チェックで投げる `BusinessException` から来ます。
  DB の一意制約違反は `ApiExceptionHandler` で扱っていません（[30-07](../30-07-member-service.md) の演習 2）。
- エラーの欄に入力チェックしか書かない: 業務エラー（重複）も、利用者に見える失敗です。
- テストに単体テストしか書かない: `members.feature` も同じ機能のテストです。

## 演習 2

### 解答

入口は `OrderImportJob.run`（`OrderImportJob.java` 41〜60 行目）です。
起動の起点は `SampleApplication.main`（`SampleApplication.java` 16〜21 行目）です。

API は「URL とメソッドを結ぶ注釈」で入口が分かります。
バッチは「起動時に動くインタフェースの実装」と「どの条件で Bean になるか」で入口が分かります。

### 理由（コードの場所）

```java title="sample-app/src/main/java/com/example/sample/order/batch/OrderImportJob.java" linenums="22"
@Component
@ConditionalOnProperty(name = "app.batch.job", havingValue = "JOB0001")
public class OrderImportJob implements ApplicationRunner, ExitCodeGenerator {
```

- `ApplicationRunner` を実装したクラスは、Spring Boot の起動完了後に `run` が呼ばれます。
- `@ConditionalOnProperty` により、`app.batch.job=JOB0001` のときだけ Bean になります。
- ジョブ ID は Javadoc（16 行目）と、この条件（23 行目）の 2 か所で確かめられます。
- 終了コードを返すため `ExitCodeGenerator` も実装しており、`SampleApplication` 18〜20 行目と組み合わさります。

### よくある誤答

- 「`SampleApplication.main` が入口なので、それで終わり」: `main` は API とバッチ共通の起動クラスです。
  ジョブ固有の処理の入口は `OrderImportJob.run` です。
- 「`OrderImportService.importLines` が入口」: これは流れの途中です。
  引数 `--input` の確認やログ出力、終了コードの決定は `OrderImportJob.run` にあります。
- `@ConditionalOnProperty` を見落とし、「常に起動時に動く」と答える。

## 演習 3

### 解答

正しくありません。
会員が存在しないときは `null` ではなく、`NotFoundException` を投げます。

### 理由（コードの場所）

```java title="sample-app/src/main/java/com/example/sample/member/MemberService.java" linenums="21"
        return mapper.findById(id).orElseThrow(() -> new NotFoundException(MessageIds.MEMBER_NOT_FOUND, id));
```

- `findById` は `Optional<Member>` を返します（`MemberMapper.java` 10 行目）。
- 空の `Optional` に `orElseThrow` を呼ぶと、渡した例外が投げられます。
- 確かめるテストは `MemberServiceTest.get_throwsNotFoundForUnknownId`（61〜67 行目）です。
  存在しない ID 99 で `NotFoundException` が投げられ、メッセージ ID が `APPE0002` であることを確かめています。

### よくある誤答

- 「`Optional` を返す」: `Optional` を返すのは `MemberMapper.findById` で、`MemberService.get` の戻り値は `Member` です。
- 「404 を返す」: `MemberService` は HTTP を知りません。
  404 に変換するのは `ApiExceptionHandler.notFound` です（[30-04](../30-04-error-response.md)）。
- テストを示さずに「コードを見たら違った」で終える: 演習では、テストでの確かめ方まで答えます。

## 演習 4

### 解答

落ちるテストは次の 2 つです。

| テスト | 落ちる理由 |
| --- | --- |
| `MemberServiceTest.get_throwsNotFoundForUnknownId` | 例外が投げられず `null` が返るため、`assertThatThrownBy` が失敗する |
| `MemberControllerTest.notFoundReturns404WithMessageId` | コントローラが `null` を返し、応答が 404 ではなく 200 になるため、`status().isNotFound()` が失敗する |

`MemberControllerTest.registerThenGet` は、存在する会員を照会するので落ちません。
`members.feature` の「存在しない会員は 404」も失敗しますが、`./gradlew test` では実行されません。

### 理由（コードの場所）

- `MemberServiceTest.java` 63〜66 行目は、例外の型とメッセージ ID を確かめています。
- `MemberControllerTest.java` 53〜56 行目は、ステータス 404 と `messageId` を確かめています。
- 例外が無ければ `ApiExceptionHandler` は呼ばれず、`@RestController` のメソッドが返した `null` がそのまま応答になります。
- Karate のテストは `build.gradle` 38〜41 行目の `excludeTags 'karate'` で `test` タスクから除外されています。

### よくある誤答

- 「`MemberServiceTest` だけが落ちる」: コントローラのテストも、サービスの実物を使っています（`MemberControllerTest.java` 30 行目）。
  そのため、サービスの変更がコントローラのテストにも影響します。
- 「Karate のテストも `./gradlew test` で落ちる」: Karate は `karateTest` タスクでだけ実行されます（[30-02](../30-02-build-gradle.md)）。
- 「`NullPointerException` で 500 になる」: `null` を返すだけでは例外になりません。
  本文が空の 200 になります。

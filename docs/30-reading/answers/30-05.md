## 演習 1

### 解答

`会員が見つかりません（会員ID: 1,234）。` になります。
数値の `1234` が、`MessageFormat` により桁区切りのカンマ付きで整形されるからです。

### 理由（コードの場所）

- `MemberService.java` 21 行目（`new NotFoundException(MessageIds.MEMBER_NOT_FOUND, id)`）で、`long` の `id` を埋め込み値として渡しています。
- `ApiExceptionHandler.java` 47 行目の `messages.getMessage(id, args, id, Locale.JAPANESE)` は、
  埋め込み値があるとき `MessageFormat` で本文を組み立てます。
- `MessageFormat` は、`{0}` に数値が来ると、言語に合った数値の形式（日本語では 3 桁ごとのカンマ）で整形します。
- 既存のテストは ID 42（`MemberControllerTest.java` 53〜56 行目（`get("/api/v1/members/42")`））だけなので、この動きに気づけません。

修正案は 2 通りあります（どちらか一方）。

```properties
# 案 1: 本文で数値の形式を指定する（桁区切り無し）
APPE0002=会員が見つかりません（会員ID: {0,number,#}）。
```

```java
// 案 2: 文字列にしてから渡す（MemberService.java 21 行目）
return mapper.findById(id).orElseThrow(() -> new NotFoundException(MessageIds.MEMBER_NOT_FOUND, String.valueOf(id)));
```

守るテスト（例。`MemberControllerTest` に追加）:

```java
    @Test
    void notFoundMessageHasNoDigitGrouping() throws Exception {
        mvc.perform(get("/api/v1/members/1234"))
                .andExpect(status().isNotFound())
                .andExpect(jsonPath("$.message").value("会員が見つかりません（会員ID: 1234）。"));
    }
```

案 1 を選ぶ場合は、テストの `StaticMessageSource` の本文（27 行目）も同じ形に変えます。
テストの本文は `messages.properties` を読まないからです。

### よくある誤答

- 「`会員ID: 1234` になる」: 埋め込み値は文字列として連結されるのではなく、型に応じて整形されます。
- 「テストで確かめているので大丈夫」: テストの ID は 2 桁なので、桁区切りが出ません。
  境界となる値（4 桁以上）を選ぶのがテストの基本です。

## 演習 2

### 解答

`member@example.com` が入ります。
前後の空白を除き、小文字にした値（正規化した値）です。

### 理由（コードの場所）

```java title="sample-app/src/main/java/com/example/sample/member/MemberService.java" linenums="26"
        String normalized = email.trim().toLowerCase(java.util.Locale.ROOT);
        if (mapper.existsByEmail(normalized)) {
```

- 26 行目で正規化し、28 行目でその `normalized` を埋め込み値として渡しています。
- 本文は `messages.properties` 3 行目の `このメールアドレスは既に登録されています（{0}）。` です。

  メールアドレスは応答の本文にだけ入ります。

## 演習 3

### 解答

ID は、エラーの次の連番 `APPE0004` にします。
変更する場所は次のとおりです。

| ファイル | 変更 |
| --- | --- |
| `sample-app/src/main/java/com/example/sample/common/MessageIds.java` | 12 行目の後に `public static final String PRODUCT_NOT_FOUND = "APPE0004";` を追加 |
| `sample-app/src/main/resources/messages.properties` | 3 行目の後に `APPE0004=商品が見つかりません（商品コード: {0}）。` を追加 |
| 例外を投げる場所 | `throw new NotFoundException(MessageIds.PRODUCT_NOT_FOUND, productCode);` |

テストは、例外を投げるサービスの単体テストで `getMessageId()` が `APPE0004` であることを確かめます。
API から返るなら、コントローラのテストと Karate のシナリオで、404 と `messageId` も確かめます。
コントローラのテストでは、`StaticMessageSource` に `APPE0004` の本文も登録します。

### 理由（コードの場所）

- ID の形式は `MessageIds.java` 6 行目（`形式: APP + 種別`）の Javadoc に従います。エラーなので `E` です。
- 既存のエラーは `APPE0001`〜`APPE0003` なので、次は `APPE0004` です。
- 「見つからない」なので、`NotFoundException` を使えば 404 になります（[30-04](../30-04-error-response.md)）。

### よくある誤答

- `messages.properties` だけに追加する: コードから文字列 `"APPE0004"` を直接書くことになり、定数を使う規則に反します。
- `MessageIds` だけに追加する: 本文が無いので、応答の `message` が `APPE0004` という ID そのものになります。
- 「`APPW0002`」: 処理を止めて利用者にエラーを返すので、警告ではなくエラーです。

## 演習 4

### 解答

`message` は、メッセージ ID そのもの（例: `APPE0002`）になります。
今のテストでは、この誤りに気づけません。

### 理由（コードの場所）

- Spring Boot は、`basename` に対応するファイル（`message.properties`）が無いと、`messages.properties` を読む仕組みを作りません。
  このとき、本文を 1 件も持たない仕組みが代わりに使われます。
- `ApiExceptionHandler.java` 47 行目の `getMessage` は、本文が見つからないと 3 つ目の引数（既定値）の `id` を返します。
  そのため、起動エラーにはならず、静かに ID だけが返ります。
- 気づけない理由:
    - `MemberControllerTest` は `StaticMessageSource` を使い、`application.yml` を読みません（26〜27 行目）。
    - `members.feature` は `messageId` だけを確かめ、`message` を確かめていません（30・36 行目）。

改善案（例）: `members.feature` の「存在しない会員は 404」に、本文の確認を足します。

```gherkin
    And match response.message == '#regex 会員が見つかりません.*'
```

### よくある誤答

- 「起動時にエラーになるので気づける」: 起動は成功します。それがこの誤りの怖いところです。
- 「`message` が `null` になる」: 既定値に `id` を渡しているので、`null` ではなく ID になります。
- 「`MemberControllerTest` が落ちる」: このテストは設定ファイルを読まないので落ちません。

## 演習 5

### 解答

本文が見つからないとき、`getMessage` は既定値として渡したメッセージ ID を返すからです。
`invalidInputReturns400` は `messageId` と `details` の件数だけを確かめ、`message` を確かめていません。

### 理由（コードの場所）

- `ApiExceptionHandler.java` 47 行目: `messages.getMessage(id, args, id, Locale.JAPANESE)`。3 つ目の引数が既定値です。
- `MemberControllerTest.java` 27 行目（`addMessage("APPE0002", ...)`）で登録しているのは `APPE0002` だけです。
- `MemberControllerTest.java` 64〜66 行目（`isBadRequest()`）は、ステータス、`$.messageId`、`$.details.length()` だけを確かめています。
  このテストの中で `message` は `APPE0001` という文字列になっていますが、確かめていないので通ります。

### よくある誤答

- 「`messages.properties` を読んでいるから」: このテストは Spring を起動しないので、`messages.properties` を読みません。
- 「入力チェックのエラーでは `message` を使わないから」: `invalid` も `body` を通るので、`message` は組み立てられています（43 行目）。
